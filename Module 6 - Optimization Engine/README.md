# Module 6 - Optimization Engine

## Overview

Module 6 is the optimization layer of the Digital Twin system. It takes the best operating scenario generated by Module 5 and the intelligent recommendations produced by Module 4, then determines an improved operating state using a real-valued Genetic Algorithm.

The module focuses on optimizing energy usage, operating cost, and carbon emissions while respecting equipment, battery, and grid constraints.

## Optimization Objectives

The optimizer uses a weighted multi-objective function containing three objectives.

### 1. Energy

The energy objective considers:

- Useful electrical energy
- Boiler fuel energy
- Curtailed renewable energy

The optimizer attempts to minimize the overall energy objective.

### 2. Cost

The cost objective considers:

- Grid electricity import
- Boiler fuel consumption
- Battery degradation
- Renewable energy export revenue

The optimizer attempts to minimize the net operating cost.

### 3. Carbon

The carbon objective considers emissions from:

- Grid electricity
- Boiler fuel consumption

The optimizer attempts to minimize total carbon emissions.

### Default Objective Weights

Energy : 35%
Cost   : 35%
Carbon : 30%

## Genetic Algorithm

Module 6 uses a small dependency-free real-valued Genetic Algorithm.

### Default Configuration

Population size : 60
Generations     : 80
Mutation rate   : 0.18
Crossover rate  : 0.85
Elite count     : 4
Tournament size : 3
Seed            : 42

### Genetic Algorithm Process

1. Initialize the population.
2. Generate candidate operating states.
3. Evaluate the fitness of each candidate.
4. Preserve elite candidates.
5. Select parents using tournament selection.
6. Generate children using real-valued crossover.
7. Apply mutation.
8. Enforce variable bounds.
9. Repeat for the configured number of generations.
10. Return the best candidate found.

---

## Constraint Handling

The optimization layer uses a ConstraintChecker to validate and repair operating states.

### Equipment Bounds

Every decision variable must remain within its configured minimum and maximum limits.

### Battery Operation

The battery cannot charge and discharge simultaneously.

### Battery State of Charge

The projected battery SOC must remain within the configured limits.

Default limits:

Minimum SOC : 20%
Maximum SOC : 90%

### Grid Import

Grid import must remain below the configured grid import limit.

### Renewable Utilization

Renewable generation is dispatched before grid energy.

Available renewable surplus can be exported subject to the configured grid export limit.

## Main Components

### contracts.py

Defines the shared contracts used by the optimization layer.

Important structures include:

- VariableBound
- OptimizationProblem
- OptimizationResult
- DECISION_VARIABLES

### optimization/genetic_algorithm.py

Implements the real-valued Genetic Algorithm used to search for an improved operating state.

### optimization/constraints.py

Handles:

- Constraint validation
- Candidate repair
- Battery SOC calculation
- Energy balance
- Grid import and export calculations

### optimization/objective.py

Calculates:

- Energy metrics
- Cost metrics
- Carbon metrics
- Weighted objective score
- Constraint penalties

### optimization/optimizer.py

Acts as the main optimization engine.

It:

1. Builds the optimization problem.
2. Creates the baseline operating state.
3. Runs the Genetic Algorithm.
4. Validates the optimized candidate.
5. Produces the final OptimizationResult.

### optimization/optimization_validator.py

Validates:

- Optimization problems
- Optimization results
- Required decision variables
- Feasibility status
- Required metrics

### recommendation/recommendation_engine.py

Converts optimized setpoint changes into actionable recommendations.

It compares the baseline operating state with the optimized state and generates recommendations when a meaningful change is detected.

### recommendation/recommendation_validator.py

Validates generated recommendations and checks:

- Required fields
- Recommendation identifiers
- Priority values
- Numeric values
- Expected impact information

### integration/optimization_controller.py

Connects Module 4 and Module 5 outputs with Module 6.

The controller:

1. Loads Module 4 recommendations.
2. Loads the Module 5 best scenario.
3. Builds the optimization problem.
4. Runs the optimizer.
5. Generates recommendations.
6. Saves Module 6 outputs.

### integration/integration_validator.py

Validates the complete Module 4/5 to Module 6 pipeline.

It checks:

- Module 5 best scenario
- Module 4 recommendations
- Optimization problem
- Optimization result
- Generated output files

### integration/integration_test.py

Runs the complete end-to-end integration test.

## Module 6 Role in the Digital Twin

Module 6 acts as the optimization and decision-refinement layer of the Digital Twin.

Modules 3, 4, and 5 provide forecasts, intelligent recommendations, and candidate operating scenarios. Module 6 evaluates these inputs and searches for an improved feasible operating state.

The final output provides:

- Optimized equipment setpoints
- Battery operating decisions
- Renewable energy utilization
- Grid interaction decisions
- Energy metrics
- Operating cost metrics
- Carbon metrics
- Actionable recommendations
- Optimization reports

This allows the Digital Twin system to move from prediction and scenario generation toward optimized operational decision-making.
